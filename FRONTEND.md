# Работа с фронтендом QORIT

Интерфейс работает с расшифровками внутри браузера. Для анализа текста,
проверки поручений и экспорта не нужны backend, ключи API или интернет.
Автоматическое распознавание выбранного аудиофайла в интерфейсе не подключено.

## Запуск

```sh
node serve-frontend.mjs
```

Откройте `http://127.0.0.1:5500`. Раздаются только разрешённые файлы
фронтенда. Из другого устройства localhost этого компьютера недоступен.

Live Server можно использовать для локальной разработки. Обычный сервер
в корне проекта, в том числе `python3 -m http.server --bind 127.0.0.1 5500`,
может открыть через HTTP `.env`, папку `media/` и другие файлы репозитория.
Поэтому для работы с записями предпочтителен `serve-frontend.mjs` с явным
списком разрешённых файлов. Не публикуйте корень репозитория в общей сети.

Браузер не читает `.env` автоматически. Выдавать этот файл клиенту ради IP
сервера небезопасно: значения и API-ключи станут доступны посетителям.
Текущему автономному фронтенду `.env` не нужен. Существующий `server.py`
возвращает заглушку, которую нельзя использовать как расшифровку.

Если порт занят Live Server, остановите его или используйте другой порт:

```sh
FRONTEND_PORT=5501 node serve-frontend.mjs
```

В PowerShell задайте `$env:FRONTEND_PORT = "5501"` перед запуском.
Сервер по умолчанию слушает только `127.0.0.1`; он не добавляет backend API.

## Основной сценарий

1. Вставьте расшифровку с именами перед репликами, загрузите TXT/JSON или
   откройте встроенный пример встречи.
2. Обработайте текст. Проверьте выделенные вопросы, факты, решения и реплики.
3. Откройте поручения. Сверьте каждое с исходной цитатой, исправьте
   ответственного и текст срока; ошибочное поручение можно исключить.
4. Если нужен контроль срока, задайте календарную дату отдельно от словесной
   формулировки. Неизвестный или относительный срок требует проверки.
5. Подтвердите проверенные поручения и меняйте статус исполнения по мере работы.
6. Скачайте текущий протокол в DOCX либо откройте печать и выберите сохранение
   в PDF. Исходные цитаты и неподтверждённые значения следует проверить до передачи документа.

Текстовый анализ работает по правилам, а не с помощью генеративной языковой
модели. Он распознаёт ряд русских и казахских действий и сроков, в том числе
в смешанной речи, отделяет явно размеченные реплики и отбирает предложения
с фактами и проблемами. Неявные формулировки могут быть пропущены;
неоднозначные назначения требуют подтверждения человека.

## Импорт локального распознавания

TXT должен содержать расшифровку в UTF-8. Имена перед репликами помогают
связать поручения с участниками:

```text
00:03 Анна: Иван, подготовь отчёт до пятницы.
00:08 Иван: Завтра отправлю презентацию.
```

Для результата локальной ASR/диаризации импортируйте JSON, который создаёт
`python test.py --diarize` в папке `results/`. Он содержит массив `segments`
с `start`, `end` (секунды), `speaker` и `text`. Подготовка CLI и моделей
описана в [README.md](README.md).

Метки `SPEAKER_00`, `SPEAKER_01` относятся к голосам только внутри конкретной
записи. После импорта сопоставьте их с именами участников вручную по записи.
До подтверждения метки нельзя считать установленными именами. Если
`speaker` равен `null`, голос не удалось надёжно определить.

Чтение имён из текста и импорт готовых меток — не голосовая диаризация.
Сам браузер в текущем проекте голосовую модель не запускает.

## Запись и аудиофайлы

Перед включением микрофона подтвердите, что участники уведомлены о записи
и ИИ-обработке. Браузер отдельно запросит разрешение микрофона. Запись
работает на localhost или HTTPS.

После остановки аудио можно скачать для локального распознавания. Выбор
готового аудиофайла также не означает, что он распознан. Аудио не
отправляется в облачные API; для получения текста нужно отдельно выполнить
локальную ASR либо импортировать уже подготовленную расшифровку.

Формат записи выбирает браузер. При необходимости преобразуйте WebM/M4A
в WAV через локальный ffmpeg, как показано в README. Кнопки записи не
подключаются к Teams, Zoom или Google Meet.

## Сроки, статусы и напоминания

Текст срока сохраняет формулировку из расшифровки, например «до конца недели».
Отдельная календарная дата нужна для однозначного вычисления приближения
срока и просрочки. Проверьте её относительно даты самого совещания.

Напоминания видны в интерфейсе, пока страница открыта. Завершённые или
исключённые поручения не требуют напоминания об исполнении. Закрытый
браузер, выключенный компьютер и другие устройства не получают фоновых
напоминаний. Рассылки по email и руководителям нет.

## Сохранение и приватность

По умолчанию результат находится в памяти страницы. Локальное сохранение
в браузере включается явно; оно может содержать расшифровку и имена, поэтому
используйте его только на доверенном устройстве. Это не серверная база,
не синхронизация и не зашифрованное хранилище.

Для переноса результата и правок используйте JSON-резервную копию и её
восстановление в интерфейсе. Сохраняйте такую копию до перезагрузки, если
локальное хранение отключено или недоступно. Аудио следует скачивать
отдельно; сохранение текстового протокола не сохраняет запись микрофона.

Ошибка `FILE_ERROR_NO_SPACE` относится к невозможности браузера записать
данные в его хранилище. При такой ошибке не считайте локальное сохранение
успешным; выгрузите доступную резервную копию и освободите место на устройстве.
В проверенном Chrome сообщения `globals-front.js` приходили из расширения,
а не из `app.js`. Изменение исходников приложения не очищает хранилище расширений.
Документы и JSON-файлы нужно хранить согласно правилам работы с данными
организации. Для демонстрации используйте обезличенные сведения.

## Экспорт

DOCX формируется из текущего результата и пользовательских правок в браузере.
Это документ OOXML, а не переименованный текст и не фиксированный серверный
пример. Отдельный backend для экспорта не нужен.

PDF создаётся печатью подготовленного протокола. Выберите в диалоге браузера
«Сохранить как PDF» и проверьте предварительный просмотр. Это не автоматическое
скачивание PDF; сохранение завершает пользователь. Блокировка всплывающего
окна или отмена печати не означает, что файл сохранён.

## Проверка

```sh
node --test tests/*.cjs
node --check app.js
```

Проверяйте интерфейс также вручную: импорт другой расшифровки должен менять
результат; правки поручения должны попадать в экспорт и резервную копию;
прошедшая календарная дата должна давать просрочку, выполненный статус —
снимать её. При узком окне элементы управления должны оставаться доступны.

Текстовые тесты не подтверждают качество ASR или диаризации. Полная таблица
соответствия ТЗ и оставшиеся ограничения приведены в [README.md](README.md).
