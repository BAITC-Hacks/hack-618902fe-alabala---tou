# Работа с фронтендом QORIT

Интерфейс отправляет аудио в локальный сервер приложения, получает расшифровку
и поручения, затем позволяет проверить и отредактировать протокол. Сервер
выполняет STT, при включённой опции — NeMo-диаризацию, затем анализ через
настроенную Ollama. Кнопка локального разбора текста по правилам остаётся
отдельным режимом и не подменяет серверную обработку при ошибке.

## Запуск вместе с API

В подготовленном Python-окружении, из корня проекта:

```sh
python server.py
```

Откройте `http://127.0.0.1:8000`. Параметры `HOST` и `PORT` читаются
сервером из `.env`; если порт изменён, используйте его в адресе.
Инструкции установки моделей, CUDA, NeMo, FFmpeg и Ollama:
[README.md](README.md).

Страница и API работают с одного адреса и порта. Фронтенд вызывает
относительные `/api/config` и `/process-audio`; CORS и отдельная настройка
IP API в JavaScript не нужны. Не открывайте страницу через Live Server,
если хотите распознавать аудио.

Сервер отдаёт только `index.html` и явный список CSS/JS. Файлы `.env`,
Python-исходники, `media/`, `models/` и `results/` через эту раздачу
недоступны. Браузер не читает `.env`; настройки Ollama и секреты в него не
передаются. Публичный `GET /api/config` содержит только:

- `max_upload_bytes` — максимальный размер запроса;
- `max_audio_seconds` — максимальную длительность записи;
- `default_diarize` — исходное состояние опции диаризации.

«Проверить API» проверяет этот маршрут, а не CUDA, модели или доступность
Ollama. Успешная проверка настроек не гарантирует успешного распознавания.

API не содержит аутентификации и базы протоколов. Используйте приложение в
доверенной сети; доступ к опубликованному порту ограничивает администратор.
Для микрофона в браузере нужен localhost или HTTPS. По HTTP на LAN-адресе
другого компьютера микрофон обычно недоступен; выберите готовый файл либо
настройте HTTPS.

## Обработка аудио

1. Выберите «↑ Выбрать аудио». Допустимы MP3, WAV, FLAC, OGG, M4A и WebM.
   Или подтвердите уведомление и согласие участников, начните запись
   микрофона и остановите её. Запись можно прослушать и скачать.
2. Укажите дату самого совещания: от неё сервер рассчитывает «завтра»,
   «в пятницу» и другие относительные сроки. При необходимости включите
   «Различать говорящих (NeMo)» и задайте число участников от 1 до 100.
   При выключенной диаризации число говорящих не передаётся.
3. Нажмите «Распознать аудио». Только это действие отправляет запись на
   сервер. Простое открытие файла или остановка микрофона не запускает
   обработку и не является готовым результатом.
4. Дождитесь ответа. Интерфейс показывает время ожидания; API возвращает
   готовый отчёт целиком и не передаёт проценты или отдельные стадии.
5. Проверьте расшифровку, предупреждения и поручения. Во вкладке «Участники»
   можно сопоставить метки голосов с именами по записи.

Запрос — `POST /process-audio` с `multipart/form-data`: `audio`,
`meeting_date`, `diarize` и необязательный `num_speakers`. Backend
локально декодирует запись через FFmpeg, распознаёт речь и получает
поручения от Ollama. Администратор должен настроить модели внутри
разрешённого контура; интерфейс не проверяет сетевые настройки Ollama.

Поручения, даты, статусы, срочность, направление и исходные цитаты берутся
из ответа API. Повторного извлечения правилами браузера не происходит.
Неизвестный исполнитель остаётся неизвестным: говорящий и ответственный
за задачу — разные поля. `SPEAKER_00` обозначает голос внутри этой записи,
а не установленное имя человека. Сопоставление голоса с именем не является
автоматической идентификацией по тембру.

Backend сейчас возвращает поручения и счётчики, но не развёрнутое
содержательное саммари. В панели «Сводка ответа сервера» отображается
фактическая сводка с явным сообщением об этом ограничении.

## Ошибки и прекращение ожидания

Ошибка сервера отображается с объяснением: неверные параметры, неподдерживаемый
формат, превышение лимита, повреждённая запись, занятый GPU, отсутствующие
модели или недоступная Ollama. При ошибке прежний протокол не выдаётся за новый
результат. Локальные правила не включаются автоматически.

Ожидание ограничено 30 минутами. «Прекратить ожидание» останавливает ожидание
браузера; API не поддерживает отмену серверной задачи. Уже начатое
распознавание может продолжаться и удерживать GPU. Автоматического повторного
запроса нет. При необходимости проверьте журнал `server.py`, затем повторите
отправку явно, когда сервер освободится.

Если API недоступен при открытии страницы на порту 5500, откройте её с адреса
`server.py`, обычно `http://127.0.0.1:8000`. Запуск Live Server не запускает
Python-модели.

## Импорт результата и отдельный текстовый режим

Кнопка «↑ TXT / JSON» принимает два вида JSON:

- Полный ответ API с `transcript` и `tasks` сразу открывается как серверный
  протокол с сохранением полей и предупреждений. Повторный анализ текста
  не выполняется.
- JSON локального CLI, созданный `python test.py --diarize`, содержит
  `segments`, но не серверные поручения. Он загружает размеченную
  расшифровку для отдельного разбора по правилам.

TXT должен содержать UTF-8-текст. Можно вставить готовую расшифровку в поле
или открыть «Пример встречи». Пример не является результатом распознавания
выбранного аудио.

«Разобрать текст по правилам» работает только в браузере, без Ollama.
`transcript-analyzer.js` распознаёт ограниченный набор русских, казахских
и смешанных формулировок, выделяет действия и сроки и отбирает факты.
Он не выполняет голосовую диаризацию и не обеспечивает понимание всех
формулировок. Имена перед репликами помогают правильно разделить текст:

```text
00:03 Анна: Иван, подготовь отчёт до пятницы.
00:08 Иван: Завтра отправлю презентацию.
```

Локальный режим ограничен 200 000 символов. Расшифровка из API допускает
до 2 000 000 символов, без скрытого обрезания. При переходе с серверного
анализа на правила текущие поручения и ручные правки заменяются; сохраните
JSON перед подтверждением, если они нужны.

Для разработки только текстового режима можно запустить:

```sh
node serve-frontend.mjs
```

Он отдаёт разрешённые ресурсы на `http://127.0.0.1:5500`, но не содержит
API. Если порт занят, задайте `FRONTEND_PORT=5501` в окружении. Обычная
раздача всего корня проекта через Live Server или `http.server` может открыть
`.env` и записи по HTTP; сервер с явным списком ресурсов предпочтительнее.

## Проверка поручений и сроков

Сверьте каждое поручение с исходной цитатой. Уточните исполнителя, суть,
словесный срок и календарную дату; неверное поручение можно исключить,
пропущенное — добавить. После проверки подтвердите поручение.

Для серверного анализа календарная дата приходит из API. Проверьте её
относительно даты встречи. В локальном режиме дату для контроля сроков
нужно указать вручную. Изменение даты совещания после серверной обработки
требует повторного запроса: прежние сроки были рассчитаны от старой даты.

Меняйте статус исполнения по фактическому ходу работы. Интерфейс показывает
просрочку и сроки в ближайшие три дня, пока страница открыта. Выполненные
и исключённые поручения не напоминают об исполнении. Фонового сервиса,
писем и доставки напоминаний при закрытом браузере нет. Серверный отчёт —
снимок на дату обработки; дальнейшие ручные правки хранятся в браузере.

## Сохранение и перенос

По умолчанию текст и правки находятся только в памяти вкладки. В разделе
«Сохранение и перенос черновика» можно явно включить локальное сохранение.
Оно содержит протокол, правки и метаданные серверного результата, но не аудио
или API-ключи. Это не синхронизация, не серверная база и не зашифрованное
хранилище. Используйте его только на доверенном устройстве.

«Сохранить JSON» скачивает резервную копию; «Открыть черновик» восстанавливает
её вместе с правками, источником анализа и статусами. Это отдельный формат
`qorit-draft`, а не исходный ответ API. Максимальный размер — 20 МиБ;
квота браузерного хранилища может быть меньше. Аудио скачивается отдельно.

Если браузер сообщает `FILE_ERROR_NO_SPACE` или превышение квоты, не
считайте черновик сохранённым. Сохраните доступную JSON-копию и освободите
место. При отключении автосохранения локальная копия удаляется, а текущий
протокол остаётся в памяти вкладки.

## Экспорт текущего протокола

«↓ DOCX» создаёт настоящий OOXML-документ в браузере из текущего протокола
и ручных правок. «Печать / PDF» открывает представление для печати: выберите
«Сохранить как PDF» и проверьте предварительный просмотр. Отмена диалога
не означает, что файл сохранён.

Эти кнопки не вызывают `/process-audio-pdf` или `/process-audio-docx`:
каждый из серверных маршрутов заново распознаёт аудио и не знает о правках
в браузере. Экспорт интерфейса сохраняет уже проверенный пользователем
результат, без повторной отправки записи.

## Проверка

```sh
node --test tests/*.cjs
node --check app.js
```

Python-проверки и подготовка тестовых зависимостей описаны в README.
Контрактные тесты подменяют GPU и Ollama; отдельные проверки декодируют
настоящие WAV/WebM через FFmpeg. Это не подтверждение точности моделей на
реальных совещаниях. После подготовки моделей отдельно проверьте сквозной
сценарий с обезличенной русской, казахской и смешанной записью.
